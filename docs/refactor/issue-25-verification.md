# #25 投票・審査員賞の全対象を更新前に検証

基準: `f3bd42d049763e2622ad929d554092666cba7e35`。base: `fix/step-11-bugs`。

通常票と審査員賞（賞だけの入力を含む）を同じ対象集合にし、Postの存在・
大会所属・自己投稿を、既存VoteのDELETEとカウンタ変更前に確認する。
ID変換・重複・点数範囲・非有限値も更新前に拒否する。
無効入力をskipして既存票だけ削除する経路を廃止した。
正当な審査員賞だけ・0点・小数点採点と有効な点数の変換は維持する。

## 検証

Python 3.11.16、一時SQLite、通信拒否。
通常票／賞だけ／有効票と不正賞混在 × 他大会／不存在／自己投稿／不正IDの
12ケースは修正前すべて失敗。既存票・賞・コメントと両大会のカウンタを照合する。
無効点数6ケースも既存票が維持されることを確認する。
特性テストは意図した400応答・取得がDELETEより前になる順序へ更新した。
全体pytest・CI・レビュー結果は個別PRに記録する。

## 影響

POST `/api/contests/<id>/vote`の不正対象・点数は400になる。
既存票の暗黙削除、他大会への投票・自己投稿への賞、無効賞の500応答を防ぐ。
成功JSON、期間判定、採点式、順位、schemaは維持し、migrationは不要。
frontendの`features/contest-detail/model/voting.ts`を確認した。
有効な数値ID・点数を送信し、未選択賞を省略するため、frontend変更は不要。
古い画面で削除済み投稿を含む入力は400になり、再読込して投票し直す。

既存の大会不一致Voteは、本番で本PRが自動削除しない。PostとのJOINで
`Vote.contest_id != Post.contest_id`、賞の自己投稿・不存在を読み取り監査し、
結果公開済み大会への影響を確認して別手順で修復する。
本PRのrevertで戻せるが不正投票経路も復活する。

やってないこと: 既存データ修復、他API入力検証、権限共通化、構成整理。
masterへはマージしない。

## レビュー指摘の追補（2026-10-06）

`judgeAward`が`[]`・`false`・`0`・`""`・`{}`の場合も400で拒否する。
未指定・nullは引き続き賞なしとして扱い、正当な票の置換・取り消しを許可する。
不正賞と有効票が混在する場合も、既存票・賞・コメント・カウンタを維持する。

通常票と賞の投稿IDは共通の変換処理で、Post.idのPostgreSQL INTEGERに合う
`1〜2147483647`の範囲を、対象投稿のDB検索より前に検証する。
上限の有効IDは受け入れ、範囲外IDは400になる。DB schema/migrationは変更しない。

# Issue #14: 投票処理の service 抽出

計画書の「順 10」の投票領域。PR #38 取り込み後の `origin/master`
(`8160b94`) から `refactor/14-voting-service` を作成した。

## 変更範囲

- `services/voting.py`: 入力値の検証、期間判定、既存票の置換、点数変換と範囲判定、
  審査員賞と0点票の補完、投票者・審査員カウンタ更新、commit と処理時間ログ。
- `blueprints/voting.py`: JSON／form／セッション読取、service 呼び出し、JSON 応答。
  ログイン判定、セッション由来の審査員フラグ、開始ログ・計測起点、例外時の
  rollback・エラーログ・標準出力を元の位置と順序で維持。
- `tests/conftest.py`: 固定時刻の差し替え先を投票 route から投票 service に移す。
- `app.py`、モデル、集計処理、他の route は変更しない。

元のソースを AST の行番号で機械的に切り出した。AST から処理を再生成していない。
抽出本体はコメントを含めてコピーし、`jsonify` の除去と検証成功時の `None` の追加
だけを戻り値の境界として調整する。service は payload とステータスを返し、
route が HTTP 応答へ変換する。検証は元と同じく try の外、DB 処理は元の try の
内側から呼ぶ。ログは既存の遅延参照 adapter で元の logger に記録し、処理時間は
route で取得した元の開始時刻から測る。

検証スクリプトは基準コミットの投票 route と比較し、2つの service 関数の

確認する。route の引数・デコレータ・JSON／form／セッション読取・HTTP 応答・
ログ・例外ハンドラ、module の import と Blueprint 定義も比較する。
`app.py` の AST が不変であることと、fixture は時刻の差し替え先だけを変更した
ことも確認する。

## 検証結果

- 移動前の既存テスト: **148 passed**。
- 移動前に追加した投票の特性テスト: **39 passed**。
- 移動後の全テスト: **187 passed**。
- 投票開始は包含、終了は除外。期間外では既存票・カウンタを変更しない。
- 一般投票の0／1と審査員の0〜上限、float 変換、小数、文字列・bool・不正値を確認。
- 一般の0点票は保存せず、審査員の0点票は保存する元の扱いを確認。
- 不正 ID、存在しない投稿、通常投票の自分の投稿はスキップし、別大会の投稿は
  元の query のまま取得・保存されることを確認。
- 審査員賞は点数付き・0点・点数なし・範囲外点数を確認。補完処理で自分の投稿に
  審査員賞が保存される扱いと、コメントの文字列がそのまま保存される扱いを確認。
- セッションの大会 ID の型、一般採点大会でも審査員セッションを採用する扱いを確認。
- 同じ票の再送信、一般／審査員の切り替え、空の送信、カウンタの減算下限を確認。
- JSON の `content` は既存処理どおり採用しない。form からの内容の改行正規化、
  文字数検証、入力不正が大会取得より先に返ることを確認。
- JSON `null` と文字数 helper の例外は元と同じく try の外にあることを確認。
- 大会なし、不正な審査員賞、賞の ID が文字列で重複票となる場合の自動 flush 失敗、
  commit 失敗は rollback し、元の票・カウンタを維持することを確認。
- 既存票削除、対象投稿取得、票の INSERT、投票者カウンタ、審査員カウンタ、commit
  の実際の SQL／呼び出し順序を確認。成功時のログ文言・順序と失敗時のログ・出力を確認。
- 全35 route と static の URL map、factory、`app:app`、CLI 名が既存契約と同等。
- 全10モデルの metadata・DDL・リレーションが snapshot と一致。
  一時 SQLite の基準スキーマに対する Alembic 差分ゼロ。
- 機械比較スクリプト、`git diff --check`: 成功。

ローカルは一時仮想環境 `netatwi-issue3-venv` の Python 3.12.14 を使用。
外部通信は fake とネットワーク拒否 fixture で隔離した。
Python 3.11 は PR の既存 GitHub Actions で確認する。
既存の SQLAlchemy・protobuf の非推奨警告は残る。

## やってないこと・戻し方

投票可能条件、0点処理、採点式、対象投稿の扱い、入力検証の漏れ、
トランザクション境界、ログ内容の改善は含まない。
DB migration、フロントエンド変更、特別なデプロイ順は不要。
問題があれば PR の3コミットをまとめて revert し、元の route に戻せる。
